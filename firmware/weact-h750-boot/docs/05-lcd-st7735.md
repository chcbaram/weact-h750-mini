# 05. LCD (ST7735S, SPI4 + DMA)

## 목적

보드에 달린 0.96" TFT 를 부트로더에서 쓴다. 다운로드 진행률을 눈으로 볼 수 있어야 하고,
USB 나 시리얼 없이도 지금 어느 모드인지 알 수 있어야 한다.

## 대상 파일

- `src/hw/driver/spi.c` — SPI4 + DMA1_Stream1
- `src/hw/driver/lcd.c` — 프레임버퍼, 그리기, 폰트
- `src/hw/driver/lcd/st7735.c` — 패널 드라이버
- `src/hw/driver/lcd/lcd_fonts.c`, `resize.c`
- `src/common/hw/include/hangul/` — 폰트 데이터

## 이식 출처

세 곳에서 각각 가장 좋은 부분을 가져왔다.

| 출처 | 가져온 것 |
|---|---|
| `stm32h5-bd/.../lcd/st7735.c` | 160×80 패널 드라이버 본체. 이미 이 해상도용이고 `lcd_driver_t` vtable + `spiDmaTxTransfer` 등 현재 API 를 쓴다 |
| **`github.com/chcbaram/stm32h750mv`** | **이 보드의 확정 파라미터.** SPI4/핀/DMA 스트림/회전값 |
| `stm32h7-w5300-dac/.../spi.c` | H7 SPI4 + DMA 드라이버 (H5 GPDMA 코드는 못 쓴다) |

## 확정 파라미터

| 항목 | 값 | 근거 |
|---|---|---|
| 패널 | ST7735S 160×80 | `HW_ST7735_MODEL 0` |
| 오프셋 | `colstart = 1`, `rowstart = 26` | 같은 보드 동작 코드 |
| 회전 | `st7735SetRotation(1)` | 같은 보드 동작 코드 |
| SPI | **SPI4**, MODE0, MSB first | |
| SCK | **PE12** (AF5) | 회로도 `LCD_SCL` |
| MOSI | **PE14** (AF5) | 회로도 `LCD_SDA` |
| CS | **PE11** (GPIO) | |
| DC | **PE13** (GPIO) | 회로도 `LCD_WR_RS` |
| BL | **PE10** (GPIO) | TIM1_CH2N 이라 PWM 도 가능 |
| DMA | **DMA1_Stream1**, `DMA_REQUEST_SPI4_TX` | Stream0 은 USART1 RX 가 쓴다 |

LCD 는 4-wire SPI 라 MISO 가 없다. **RESET 은 GPIO 가 아니라 보드 `SYS_RESET` 네트**에
물려 있어 패널이 MCU 와 함께 리셋된다.

## 프레임버퍼는 D2 SRAM 에

```c
static uint16_t __attribute__((section(".non_cache"), aligned(64)))
    frame_buffer[1][HW_LCD_WIDTH * HW_LCD_HEIGHT];   // 160*80*2 = 25,600 B
```

- SPI4 TX DMA 가 여기서 **직접 읽어간다.** D-Cache 를 켠 상태에서 캐시 가능한 메모리를
  DMA 소스로 쓰면 CPU 가 쓴 내용이 아직 캐시에만 있어 화면이 깨진다.
- SPI4(APB2)와 DMA1 이 D2 도메인이라 접근도 자연스럽다.

## 함정

### 1. MspDeInit 의 핀 목록이 MspInit 과 다르면 남의 핀을 죽인다 — 실기에서 물림

증상: **LCD 가 아예 안 나옴.** `lcdInit()` 은 `[OK]` 를 찍고 SPI4 레지스터도 정상이었다
(`CR2 TSIZE = 0x3200` = 12800 = 160×80, `CFG1 DSIZE` = 16bit, AF5 설정됨).

진단: 단계별로 `GPIOE->MODER` 를 찍었다.

```
MODER after gpio : 0xF75FFF7F   <- PE10 = 01 (출력)
MODER after spi  : 0xF77FFF6F   <- PE10 = 11 (아날로그!)
```

`gpioInit()` 과 `spiInit()` 사이에서 백라이트 핀이 아날로그로 되돌아갔다. 그 사이에 있는
것은 `qspiInit()` 이고, 원인은 이식하면서 **`HAL_QSPI_MspInit` 만 고치고
`HAL_QSPI_MspDeInit` 을 안 고친 것**이었다.

원본(`convex-boot`)은 QSPI **BK2(PE7~PE10)** 를 쓴다. 이 보드는 **BK1** 이고
**PE10 은 LCD 백라이트**다. `BSP_QSPI_Init()` 이 맨 앞에서 `HAL_QSPI_DeInit()` 을 부르므로
`HAL_GPIO_DeInit(GPIOE, PIN_7|8|9|10)` 이 실행되어 백라이트 핀이 리셋됐다.

`spi.c` 에도 같은 종류의 버그가 있었다 — `HAL_SPI_MspDeInit` 이 `Instance == SPI3` 와
비교하는 오타라 사실상 아무 일도 하지 않았고, 핀 목록도 원본 것(PE6)이었다.

**교훈: MspInit 을 고치면 MspDeInit 도 같은 핀 목록으로 반드시 함께 고친다.**

### 2. 백라이트는 active LOW

회로도 `06-TFT-LCD.SchDoc` : **SI2301(P채널 MOSFET)**, 소스가 3V3, 게이트가 **R37 10K 로
3V3 에 풀업**. P채널은 게이트를 소스보다 낮춰야 켜지므로 `LCD_LED` 를 **LOW 로 당겨야 점등**된다.

한 번 틀렸던 이유를 남겨둔다. `chcbaram/stm32h750mv` 의 `gpio_tbl` 에도 `on_state` 필드가
있고 백라이트 행이 `_DEF_HIGH` 로 되어 있어 active HIGH 로 판단했었다. 그런데 **그 쪽
`gpioPinWrite()` 는 `on_state` 를 아예 무시하고 생짜 레벨을 쓴다.** 그 테이블 값으로 극성을
추론하면 안 된다.

우리 `gpioPinWrite()` 는 `on_state` 를 쓰므로, BL 행만 뒤집어 두면 상위 API 의미
("true = 켜짐")가 유지된다.

```c
{GPIOE, GPIO_PIN_10, _DEF_OUTPUT, GPIO_PIN_RESET, GPIO_PIN_SET, _DEF_LOW, NAME_DEF(LCD_BL)},
//                                ^on_state = LOW 를 출력 = 점등
```

### 3. `#ifdef HW_LCD_LVGL` 은 0 으로 정의해도 참이다

`lcd.h` 와 `lcd.c` 가 `#ifdef` 로 검사해서, 끄려고 `0` 을 정의해도 lvgl 헤더를 끌어왔다.
`#if defined(...) && (... > 0)` 으로 고쳤다.

## 폰트 크기 — 3개 테이블 전부 타입이 낭비였다

LCD 를 넣자 FLASH 가 47KB → **104,808 B (81.2%)** 로 뛰었다. USB/UF2 가 아직 안 들어간
상태라 그대로는 128KB 에 못 들어간다. 원인은 폰트 데이터였고, 세 테이블 모두 실제 값보다
넓은 타입을 쓰고 있었다.

| 테이블 | 원래 | 실측 최대 | 바꾼 타입 | 절약 |
|---|---|---|---|---|
| `K_font[360][32]` | `uint16_t` 23,040 B | `0xFF` | `uint8_t` | **11,520 B** |
| `wWanToJohabTable[2350]` | `uint32_t` 9,400 B | `0xD3B7` | `uint16_t` | **4,700 B** |
| `wEngFon[0x60][16]` | `int` 6,144 B | `0xFF` | `uint8_t` | **4,608 B** |

소비하는 쪽도 전부 확인했다. `K_font`/`wEngFon` 은 `uint8_t`인 `FontPtr->FontBuffer[]` 에
들어가고(일부는 이미 `(uint8_t)`/`(char)` 캐스팅까지 하고 있었다), `wWanToJohabTable` 은
`hanCnvCodeWan2Johab()` 의 반환형이 이미 `uint16_t` 라 **어차피 잘려 나가고 있었다.**

여기에 더해 부트로더는 `HW_LCD_HANGUL 0` 으로 한글 글리프를 뺀다. ASCII(`font_eng.h`)는
그대로라 `LCD_FONT_HAN` 으로도 영문은 정상 출력되고, 한글은 **빈 사각형**으로 그려서
빠졌다는 것이 화면에 드러나게 했다. 앱에서는 켜면 된다.

`han.h` 가 `hw_def.h` 를 포함하지 않아 `HW_LCD_HANGUL` 이 보이지 않던 것도 함께 고쳤다.
(이것 때문에 처음엔 스위치가 전혀 먹지 않았다)

## 검증 방법

1. 부팅 시 LCD 에 스플래시(보드명/버전/QSPI 용량/클럭 + 하단 파란 바)가 뜬다
2. 글자가 정방향/정색인지. 미러링이나 오프셋이 틀리면 `colstart`/`rowstart`/`MADCTL` 수정
3. `GPIOE->MODER` 로 PE10=01(출력), PE12/PE14=10(AF) 확인
4. `GPIOE->ODR` bit10 = 0 이어야 백라이트 점등

## 실측 결과

**LCD 정상 출력 확인.**

```
MODER after lcd : 0xE65FFF6F
  PE10 = 01 (출력)   PE11 = 01 (출력)   PE12 = 10 (AF5)
  PE13 = 01 (출력)   PE14 = 10 (AF5)
ODR = 0x00002800
  bit10 = 0 -> 백라이트 점등 (active low)
  bit11 = 1 -> CS idle
  bit13 = 1 -> DC
```

빌드 크기 (126KB 중):

| 시점 | FLASH | 비고 |
|---|---|---|
| 2단계(QSPI)까지 | 47,536 B (36.8%) | |
| LCD 추가 직후 | 104,808 B (81.2%) | 폰트가 대부분 |
| 폰트 타입 축소 + 한글 제외 | **66,968 B (51.9%)** | |

한글을 켠 빌드는 88,584 B — 타입 축소가 실제로 16,220 B 를 줄였다
(`K_font` 11,520 / `wWanToJohabTable` 4,700 심볼 크기로 확인).

D2RAM 은 3,232 B → **28,832 B** (프레임버퍼 25,600 B 가 `.non_cache` 에 제대로 배치됨).
