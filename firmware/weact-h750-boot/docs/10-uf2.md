# 10. UF2 (MSC 드래그앤드롭)

## 목적

`.uf2` 파일을 마운트된 볼륨에 끌어다 놓으면 QSPI 에 펌웨어가 구워지고 재부팅되게 한다.
**호스트 쪽 도구가 전혀 필요 없는** 유일한 업데이트 경로다.

## 대상 파일

- `src/ap/modules/uf2/{uf2.c, uf2.h, uf2_def.h, uf2_disk.c}`
  (`stm32h5-boot` 에서 가져오되 슬롯 구조를 걷어내고 단일 영역용으로 다시 씀)

## FAT12 가 아니라 FAT16 인 이유

**FAT12 는 클러스터 4085개가 한계**다. 512B 섹터면 약 2MB 까지밖에 표현할 수 없다.

UF2 파일은 512B 블록마다 페이로드가 256B 뿐이라 **원본 바이너리의 약 2배**가 된다.
앱이 1MB 면 `.uf2` 는 2MB 다. FAT12 볼륨으로는 호스트가 "용량 부족"으로 복사를 거부한다.

FAT16 은 65524 클러스터까지 되므로 여유가 크다. 이 프로젝트는 **16MB(32768섹터 × 512B)**
로 잡았다.

> `baram-qmk-h7s-boot` 등 예전 프로젝트는 8블록짜리 FAT12 정보 디스크를 쓴다. 그건
> README 만 보여주는 읽기 전용 디스크라 문제가 없었다. UF2 쓰기를 하려면 FAT16 이어야 한다.

## 펌웨어 상한은 디스크 크기가 정한다

```c
#define UF2_DISK_BLOCK_NUM  32768    // FAT16 지오메트리. 16MB. 부트섹터에 하드코딩
#define UF2_DISK_DATA_LBA   289      // 부트 1 + FAT x2 (128x2) + 루트 32
#define UF2_MAX_FW_SIZE     ((UF2_DISK_BLOCK_NUM - UF2_DISK_DATA_LBA - 1) * UF2_PAYLOAD_SIZE)
```

부트섹터를 손으로 만들었고 총섹터 `0x8000`, FAT당 128섹터가 **하드코딩**되어 있다.
`UF2_DISK_BLOCK_NUM` 은 펌웨어 크기에 연동시키면 안 된다. 반대로 **펌웨어 상한을
디스크에서 유도**한다.

한계가 두 개다. 작은 쪽이 이긴다.

| | 값 |
|---|---|
| (a) QSPI 앱 영역 | `FLASH_SIZE_FIRM - FLASH_SIZE_TAG` = 8MB − 4KB = 8,384,512 B |
| **(b) FAT16 디스크 데이터 영역** | **(32768 − 289 − 1) × 256 = 8,314,368 B** |

**(b)가 이긴다.** `.uf2` 는 512B 블록마다 페이로드가 256B 라 **바이너리의 정확히 2배**다.
즉 디스크 데이터 영역 16,628,736 B 가 담을 수 있는 바이너리는 그 절반이다.

차이는 70,144 B 다. 이걸 되찾으려면 부트섹터 지오메트리(총섹터·FAT크기·LBA 오프셋)를
전부 다시 만들어야 한다. 70KB 를 위해 동작하는 FAT 를 건드릴 이유가 없다.
CDC/HID/SWD 경로는 이 제한을 받지 않으므로 8MB 를 꽉 채워야 하면 그쪽을 쓴다.

### 왜 예전에 2MB 였나

하드웨어 제약이 아니었다. 참조 프로젝트에서 그대로 가져온 상수다.

상한을 올리는 비용은 비트맵 두 개의 RAM 뿐이다.

| | 2MB | 8119KB |
|---|---|---|
| `writtenMask` (`MAX_BLOCKS/8+1`) | 1,037 B | 4,073 B |
| `erase_map` (`ERASE_SECTOR_MAX/8`) | 64 B | 254 B |
| **빌드 RAM 합계** | **34,720 B (6.62%)** | **37,952 B (7.24%)** |

AXI SRAM 512KB 중 7.24% 다. 3.2KB 를 아끼려고 상한을 1/4 로 묶을 이유가 없었다.

### 올림 나눗셈이 필요하다

`UF2_MAX_FW_SIZE` 가 더 이상 4KB 배수가 아니다 (8,314,368 = 4096 × 2029.9).

```c
#define UF2_ERASE_SECTOR_MAX  ((UF2_MAX_FW_SIZE + UF2_ERASE_SECTOR_SIZE - 1) / UF2_ERASE_SECTOR_SIZE)
static uint8_t erase_map[(UF2_ERASE_SECTOR_MAX + 7) / 8];
```

내림하면 마지막 섹터를 덮는 비트가 `erase_map` 밖으로 나간다. 예전에는 2MB/4096 = 512 가
8의 배수라 우연히 맞았다.

## 쓰기 경로

`targetAddr` 은 `uf2conv.py --base 0x0` 로 만들었으므로 **0 기준 오프셋**이다.
앱 본체가 시작하는 `0x90001000` 을 더한다.

```
flashWrite(FLASH_ADDR_FIRM + FLASH_SIZE_TAG + targetAddr, ...)
```

세 가지가 중요하다.

1. **섹터를 전송당 한 번만 지운다** (`erase_map` 비트마스크). UF2 블록은 순서가 뒤죽박죽
   으로 오고 같은 4KB 섹터에 여러 블록이 들어간다. 매번 지우면 앞서 쓴 내용이 날아간다.
2. **중복 블록을 건너뛴다** (`writtenMask`). 호스트가 같은 블록을 다시 보내는 경우가 있다.
   다시 기록하면 길이가 두 번 반영되고 소거가 다시 걸린다.
3. **누적이 아니라 최대 끝 오프셋을 기록한다** (`flash_len`). 순서가 보장되지 않으므로
   더하기로 길이를 세면 틀린다.

## 태그를 마지막에 쓴다

`uf2FlashFlush()` 가 본체를 다시 읽어 CRC 를 계산하고 태그를 쓴다. 이게 **커밋 마커**다.
태그는 독립된 4KB 섹터라 앱 본체를 건드리지 않고 쓸 수 있다(00 문서).
중간에 전원이 끊기면 태그가 무효라 부트로더가 점프를 거부한다 — 벽돌이 되지 않는다.

CRC 는 굽는 경로와 같은 **indirect** 로 다시 읽어 계산한다(07 문서).

## complete_cb 재진입 방지

호스트는 전송이 끝난 뒤에도 FAT/디렉터리 갱신으로 `write10` 을 더 보낸다. 그때마다
`tud_msc_write10_complete_cb` 가 다시 불리므로, 한 번 마무리한 전송을 재실행하지 않도록
`is_done_req` 로 막는다.

## 완료 후 상태머신

`uf2Update()` 는 **USB 콜백 밖(메인 루프)** 에서 돈다. 콜백 안에서 플래시를 굽거나 점프하면
USB 스택이 멈춘다.

```
0 : 완료/점프 요청 대기
1 : UF2_COMPLETE_WAIT_MS(1000ms) 대기 - 호스트의 FAT 기록 + SYNCHRONIZE_CACHE 완료를 기다린다
2 : bootVerifyFirm() 후 점프. 실패하면 되돌려서 다시 복사할 수 있게 한다
```

## family ID

`0xFFFF0004`. 사용자의 다른 보드와 겹치지 않는다
(`0xFFFF0002` qmk-h7s, `0xFFFF0003` h5-w6300, `0xFFFF0010~15` convex).

`uf2conv.py --base 0x0 --family 0xFFFF0004` — **`--base 0x0` 은 필수다.**
안 주면 스크립트 기본값 `0x2000` 때문에 8KB 구멍이 생긴다.

## 함정

- **`#if CFG_TUD_MSC` 앞에 `tusb.h` 를 포함**해야 한다. 안 그러면 매크로가 정의되지 않아
  `uf2_disk.c` 전체가 조용히 사라지고 링크 에러로만 드러난다.
- **볼륨 라벨은 FAT 부트섹터에 하드코딩**되어 있다(정확히 11바이트).
  `UF2_VOLUME_LABEL` 을 바꿔도 부트섹터 바이트 배열을 함께 고쳐야 한다.
  루트 디렉터리 엔트리에도 같은 라벨이 한 번 더 들어간다.

**FAT16 16MB 볼륨 마운트 확인.**

```
$ df -h /Volumes/H750BOOT
/dev/disk4   16Mi  1.5Ki   16Mi     1%   /Volumes/H750BOOT

$ cat /Volumes/H750BOOT/README.TXT
WEACT-H750-BOOT

Board   : WEACT-H750
Boot Ver: V260829R1
FamilyID: 0xFFFF0004
Max FW  : 2048 KB

FIRM    : none

Drop a .uf2 file here to update.
```

README 가 실시간으로 만들어지고 `FIRM : none` 이 QSPI 가 비어 있음을 정확히 반영한다.

**[미확인]** 실제 `.uf2` 드롭은 9단계에서 앱이 생긴 뒤에 확인한다.
