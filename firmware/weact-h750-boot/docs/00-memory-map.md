# 00. 메모리 맵

## 목적

부트로더와 앱이 각각 어디에 놓이는지, 그리고 그 배치가 왜 그래야만 하는지를 고정한다.
이 문서의 값들은 `src/hw/hw_def.h` 와 `src/bsp/ldscript/*.ld` 에 그대로 들어가며,
**앱 프로젝트(`weact-h750-fw`)와 반드시 동일해야 한다.**

## 대상 파일

- `src/hw/hw_def.h` — `FLASH_ADDR_*` / `FLASH_SIZE_*`
- `src/bsp/ldscript/STM32H750VBTx_BOOT.ld`
- `src/common/def.h` — `firm_ver_t`, `firm_tag_t`

## 내부 플래시 — 부트로더 전용 (128KB @ 0x08000000)

| 주소 | 크기 | 용도 |
|---|---|---|
| `0x08000000` | 1 K | `VECTOR` — 부트로더 벡터 테이블 |
| `0x08000400` | 1 K | `VER` — 부트로더 `firm_ver_t` |
| `0x08000800` | 126 K | `FLASH` — 부트로더 코드 |

### 왜 앱을 내부 플래시에 두지 않는가

STM32H750 의 내부 플래시는 **128KB 짜리 섹터 하나**다. 부트로더가 무언가를 지우려면
자기 자신을 지워야 한다. 그래서:

- 앱을 내부 플래시에 둘 수 없다 (부트로더와 같은 섹터가 된다).
- **플래시 기반 부트 로그도, NVS 도 둘 수 없다.** `stm32h5-w6300` 은 이것들을 bank2 에
  두지만 H750 에는 bank2 가 없다. 영구 카운터는 전부 RTC 백업 레지스터로 간다
  (이 보드는 VBAT(BAT54C)와 LSE 가 있어 유효하다).
- 향후 필요해지면 두 번째 SPI 플래시(U8, SPI1)로 옮긴다.

## QSPI — 애플리케이션, XiP (8MB @ 0x90000000)

| 주소 | 크기 | 용도 |
|---|---|---|
| `0x90000000` | **4 K** | `TAG` 섹터 — `firm_tag_t` (오프셋 0), 나머지 예약 |
| `0x90001000` | 1 K | 앱 `VECTOR` → `_fw_flash_begin`, 앱이 `SCB->VTOR` 를 여기로 |
| `0x90001400` | 1 K | 앱 `VER` — `firm_ver_t` |
| `0x90001800` | 8M − 6K | 앱 코드 + rodata |

### 왜 TAG 가 1KB 가 아니라 4KB 인가

**W25Q64 의 최소 소거 단위가 4KB** 이기 때문이다. 태그를 1KB 로 잡으면 태그와 앱 벡터
테이블이 같은 4KB 섹터 안에 들어간다. 그러면 태그를 갱신하려고 섹터를 지우는 순간
**앱의 벡터 테이블이 함께 날아간다.**

태그를 독립 섹터로 분리하면 세 가지가 가능해진다.

1. 부트로더가 앱 본체를 건드리지 않고 태그만 쓰거나 지울 수 있다.
2. 다운로드를 시작할 때 태그 섹터를 먼저 지워 **즉시 무효화**할 수 있다. 중간에 전원이
   끊겨도 "태그 없음" 상태라 부트로더가 점프를 거부한다 — fail-safe.
3. 태그 없는 이미지에 **부트로더가 나중에 태그를 만들어 넣을 수 있다** (07 문서의 2단계 승격).

`0x90001000` 은 4KB 정렬이므로 `SCB->VTOR` 가 요구하는 정렬(H7 벡터 개수 기준 1KB)을
여유 있게 만족한다.

### 단일 영역, A/B 슬롯 없음

QSPI 8MB 전체가 하나의 펌웨어 영역이다. UF2 드롭은 실행 중이던 앱을 그대로 덮어쓴다.
그래도 벽돌이 되지 않는 이유는 **태그를 마지막에 쓰기** 때문이다 — 중간에 끊기면 태그가
무효라 부트로더가 점프를 거부하고 부트 모드에 머무른다. 부트로더 자체는 내부 플래시에
있고 리셋 더블클릭으로 항상 진입할 수 있다.

향후 데이터/리소스 영역은 QSPI 를 쪼개는 대신 **두 번째 SPI 플래시(U8)** 에 둔다.

## RAM

| 영역 | 주소 | 크기 | 용도 |
|---|---|---|---|
| `NO_INIT` | `0x20000000` | 8 K | `.noinit` — `fault_log`. 리셋에도 살아남는다 |
| `DTCM` | `0x20002000` | 120 K | 빠른 스크래치 (`.dtcm`) |
| `RAM` | `0x24000000` | 512 K | AXI SRAM. `.data`/`.bss`/heap/stack |
| `D2RAM` | `0x30000000` | 288 K | `.non_cache` — LCD 프레임버퍼, DMA 버퍼 |

### 왜 주 RAM 이 DTCM 이 아니라 AXI SRAM 인가

크기(512K)와 **DMA 접근성** 때문이다. DTCM 은 CPU 전용 버스에 붙어 있어 DMA1/DMA2 가
아예 접근하지 못한다.

### 왜 DMA 버퍼는 D2 SRAM 인가

두 가지가 겹친다.

- **D-Cache 를 켜고 쓰기 때문.** DMA 가 캐시 가능한 메모리에 쓰면 CPU 는 옛 캐시 라인을
  읽는다. MPU 로 non-cacheable 로 잡은 영역에 두면 캐시 유지보수 코드가 통째로 필요 없다.
- **SPI4(APB2)와 DMA1/2 가 D2 도메인에 있다.** 같은 도메인이라 접근이 자연스럽다.

`.non_cache` 는 **링커스크립트에 반드시 선언해야 한다.** 선언하지 않으면 orphan 섹션이
되어 startup 의 `.data` 복사에도 `.bss` 클리어에도 포함되지 않고 부팅 시 쓰레기값이 남는다.

## 이미지 식별 구조체

```c
typedef struct {
  uint32_t magic_number;      // "VER " = 0x56455220
  char     version_str[32];
  char     name_str[32];
  uint32_t firm_addr;         // = _fw_flash_begin
  uint32_t firm_size;         // = _fw_flash_end - _fw_flash_begin  (0 이면 미신고)
} firm_ver_t;

typedef struct {
  uint32_t magic_number;      // "TAG " = 0x54414720
  uint32_t fw_addr;
  uint32_t fw_size;
  uint32_t fw_crc;
  uint32_t tag_crc;
} firm_tag_t;
```

`firm_size` 는 이 프로젝트에서 새로 추가한 필드다. **CRC 는 자기 이미지 안에 넣을 수
없지만(닭-달걀) 크기는 링커가 링크 시점에 안다.** 이 비대칭 덕분에 태그가 없는
이미지(아두이노 코어 빌드 등)도 크기를 스스로 신고할 수 있고, 부트로더가 CRC 를 계산해
태그를 만들어 줄 수 있다. 자세한 내용은 07 문서.

기존 구조체 뒤에 붙였으므로 다른 프로젝트와 바이너리 호환이 유지된다.
